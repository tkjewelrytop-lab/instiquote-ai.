# InstiQuote AI 官網與可操作 Web 原型

繁體中文、手機優先的公司官網與校園採購工作台。官網介紹 InstiQuote AI 品牌、服務流程與功能，並提供老師、供應商、管理員和總後台四類工作台入口；工作台包含分階段有效報價、需求版本更新、WhatsApp 演示通知中心與帳號權限管理。無需安裝前端依賴。

官網內容暫作模擬展示，正式公司名稱、地址、聯絡電郵與電話暫不填寫。頁面提供品牌使命、採購流程、功能介紹、私隱說明與常見問題；目前仍為瀏覽器本地原型。

現有公開網站：[InstiQuote AI 官網](https://tkjewelrytop-lab.github.io/instiquote-ai./)。本次新增流程須隨本版程式碼完成部署後才會顯示。

- [老師工作台](https://tkjewelrytop-lab.github.io/instiquote-ai./workspace.html?role=teacher)
- [供應商工作台](https://tkjewelrytop-lab.github.io/instiquote-ai./workspace.html?role=supplier)
- [管理員工作台](https://tkjewelrytop-lab.github.io/instiquote-ai./workspace.html?role=admin)
- [總後台](https://tkjewelrytop-lab.github.io/instiquote-ai./workspace.html?role=superadmin)

## 本地運行

安裝 Node.js 後，在本目錄運行 `node server.cjs`，打開 http://127.0.0.1:4173/。

首頁為公司官網 `docs/index.html`，由官網選擇角色後進入 `docs/workspace.html`。也可直接在瀏覽器打開這些檔案；本地文件模式的持久化行為依瀏覽器而異。

工作台支援 `workspace.html?role=teacher`、`?role=supplier`、`?role=admin` 及 `?role=superadmin` 入口；可加上 `view` 指定初始頁面，例如 `workspace.html?role=admin&view=whatsapp`。網址參數只選擇演示工作台，不代表正式登入或權限驗證。

## 體驗流程

1. 先瀏覽公司官網，了解服務流程，再使用角色入口進入工作台；工作台的品牌連結可返回官網。
2. 選擇「老師」：新建需求，完成三步表格，演示驗證碼為 `123456`。
3. 切換「供應商」：在上方選擇演示帳號，使用該帳號綁定的公司接單、填寫報價。
4. 切換「管理員」：審核供應商所交報價；分別標記待審、有效、待澄清、不符合需求、已失效或待重確認。只有目前需求版本、仍在有效期且公司資格合適的有效報價計入五份目標。
5. 可先交付目前已核為有效的報價，不必等齊五份。缺額可在第二階段繼續尋找新供應商；已交付而仍有效的方案保留。
6. 回到「老師」：查看已交付的全部有效報價及其供應商聯絡資料，自行挑選 1 至 3 間細談。可移除、另選；這是洽談名單，不代表成交。
7. 收集結束時分清零份、部分及已達目標的結果；老師可接受現有結果、延期繼續收集、調整需求或取消，並記錄原因。
8. 修改需求時必須說明原因並延後老師收集截止；系統保存舊版本，通知歷史參與者；仍可參與的已報價者須重新確認或修訂，原報價不能直接沿用為新版本有效報價。已退出、失約或不符新條件者只接收知情通知，不會被要求繼續交報。
9. 切換「總後台」管理老師、供應商與管理員帳號，設定角色權限及查看操作紀錄。總後台「重置演示數據」可恢復示例。

比較欄位樣本見 `docs/quote-sample.html`。各公司的報價格式可以不同；數量、單價、包含項目、額外費用、日期、人員、材料及付款條件均為閱讀及澄清參考，不強制供應商使用相同表格。老師按原報價內容自行篩選。

## 帳號與權限管理

上方「演示帳號」選單可切換目前類型的帳號。老師、供應商、管理員及總後台有獨立的工作台入口；一般管理員按營運、審核或唯讀角色操作，總後台負責帳號及權限設定。

- **老師／供應商帳號**：新增、搜尋、篩選、編輯、啟用與停用帳號。老師綁定學校，供應商綁定公司；同公司可有多位聯絡人。帳號狀態與供應商公司審核／停權狀態分開管理。
- **管理員控制**：新增或編輯管理員，分配營運、審核及唯讀角色，管理啟用狀態。
- **角色與權限**：矩陣控制需求、供應商、WhatsApp、報表、用戶帳號、管理員、角色及審計的查看與寫入權限。總後台可即時調整，一般管理員不能授予高於自身的權限。
- **登入流程**：支援登出演示、重新登入演示及「重設登入（演示）」，不儲存密碼，也不發送邀請或重設電郵。
- **保護與紀錄**：最後一名已啟用擁有人不能停用或降權，總後台完整權限不能移除；帳號新增、編輯、狀態與角色變更及登入重設均記錄在帳號操作紀錄。

老師只會看到自己的需求，舊需求會固化為所屬帳號 ID；修改或重用老師電郵不會轉移需求。供應商工作台固定使用目前帳號綁定的公司。同一網址的其他分頁更新帳號狀態後，畫面會同步載入最新資料，避免停用狀態被舊分頁覆寫。

## WhatsApp 通知中心

入口：具有查看權限的管理員／總後台側欄「WhatsApp 通知」。只有具發送權限的帳號可建立待發送通知、預覽、模擬送達／失敗及重試；唯讀角色只可查看。

目前有 13 個繁體通知範本：需求提交、報價邀請、接單進度、收到待審報價、有效報價交付、交報／修訂提醒、老師洽談名單、分階段交付、需求更新延期、下一階段收集、老師取消確認、供應商取消通知及洽談名單更新。模型事件會以穩定事件及收件人鍵去重建立相應演示通知。新交報只報告進度，不把待審報價當成有效方案交付。

需求更新、下一階段、取消或報價修訂後，過時的待發送／失敗通知會撤銷。發送及重試會再次核對需求版本、階段、報價修訂及名單快照，防止發送舊交期或舊報價聯絡內容。取消後只保留取消通知可發送。範本尚未提交 Meta 審核，所有發送均為瀏覽器本地演示，不會聯絡真實收件人。

## 舊版資料

同一瀏覽器及網址下的既有需求、供應商、草稿和操作紀錄會保留，業務文字會轉為繁體；訂單編號及數量不會重設。附件原始檔名、網址、聯絡欄位及資料結構值保持原樣。舊版「已選擇」資料會遷移成洽談名單，不被當作成交；需求、報價及事件 ID 保留。不同部署網址之間不會自動共用或搬移本地資料。

## 範圍

- 瀏覽器 `localStorage` 保存需求、報價、通知、帳號設定及操作記錄；演示登入選擇儲存在分頁的 `sessionStorage`。不同設備、瀏覽器及網址之間不共享。
- **四類帳號、登入及權限功能是瀏覽器端流程原型，不是正式驗證或伺服器端存取控制。** 不儲存密碼、不發送登入電郵，請使用模擬資料體驗。
- 手機驗證、WhatsApp、郵件及 AI 尚未接入真實服務。
- 附件只記錄文件名、大小和類型，不上傳或存儲文件內容。
- 供應商資料、報價及聯絡資料為模擬數據；請勿輸入真實敏感資料。
- 邀請回覆期限、接單承諾交報期限、老師收集截止分開記錄。默認邀請 12 小時內回覆，接單後 24 小時內交報，兩者均不超過老師收集截止；可由工作台使用合適期限。
- 五份目標計算的是合資格、目前版本、未過期且已核為有效的報價。退出、失約及無效報價不會永久占用接單名額；補派仍須有未參與且符合條件的公司。
- 到期判定及通知排隊在瀏覽器開啟或重新載入時執行；關閉所有分頁後沒有背景排程，也不會發出真實通知。正式上線需要伺服器時鐘、工作佇列、資料庫及真實收件渠道。
- 取消會停止接單、派單、交報、審核及留言，保留歷史並撤銷過時催報；不會因本次取消或改規格自動扣分。
- 有效性審核不等於對教學品質或採購合規的保證。正式採購仍由學校按適用程序處理。

## 發佈到 GitHub Pages

本專案使用靜態檔案，無需建置或安裝前端依賴。

1. 將專案檔案提交到 GitHub 儲存庫的 `main` 分支。
2. 打開儲存庫 **Settings → Pages**。
3. 在 **Build and deployment** 中，將 **Source** 設為 **Deploy from a branch**。
4. 將分支設為 **main**，目錄設為 **/docs**，點擊 **Save**。
5. 等待 Pages 部署完成，使用該頁面返回的網站連結存取原型。

`docs/.nojekyll` 用於直接發佈靜態資源。所有頁面資產使用相對路徑，適合儲存庫子路徑部署。
