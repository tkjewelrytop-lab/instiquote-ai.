# InstiQuote AI 校園採購工作台

繁體中文、手機優先的可操作 Web 原型：老師發佈需求、供應商獨立報價、管理員跟進派單，老師比較方案並選擇供應商。新增 WhatsApp 通知中心，集中體驗訊息範本、待發送佇列及發送結果。

## 本地運行

安裝 Node.js 後，在專案目錄運行：

```sh
node server.cjs
```

瀏覽器打開 <http://127.0.0.1:4173/>。專案無第三方運行依賴，也可直接打開 `docs/index.html`；本地檔案模式的資料持久化行為依瀏覽器而異。

## 操作體驗

1. 頂部切換「老師」，新建報價需求，完成三步表格。演示驗證碼為 `123456`，不會發送真實短訊。
2. 切換「供應商」，選一間演示公司，對同一需求確認接單並填寫報價。
3. 切換「管理員」，查看派單、審核供應商、補派，或結束收集並交付現有報價。
4. 回到「老師」，收到五份報價或管理端結束收集後，可比較匿名方案、確認選擇並查看獲選供應商的模擬聯絡資料。
5. 在管理員側欄打開「WhatsApp 通知」，體驗下述通知流程。
6. 側欄「重置演示數據」會清除目前瀏覽器中的修改，並恢復示例需求及通知。

## WhatsApp 通知中心

入口：**管理員 → WhatsApp 通知**。

- 查看老師及供應商的演示通知、收件人、需求編號、訊息內容、狀態及重試次數。
- 內建七個繁體中文範本：需求提交確認、供應商報價邀請、供應商接單進度、收到新報價、報價已備妥、供應商截止提醒、老師選定供應商。
- 點擊「建立通知」，選擇範本、關聯需求及適用供應商，預覽內容後「加入待發送」。收件人及數字由需求自動帶入。
- 待發送訊息可「模擬發送」或在詳情中「模擬失敗」；失敗後可重試，再模擬送達。系統會保存各次操作紀錄。
- 老師提交需求、派單、供應商接單、提交報價、報價備妥、結案及選定供應商等業務動作，會自動建立對應的待發送通知。截止提醒亦可使用範本手動建立。
- 供應商邀請及提醒不包含學校名稱或老師聯絡資料；老師選定前，供應商身份維持匿名。選定通知只顯示獲選供應商的模擬聯絡資料。

**這些功能沒有連接真實 WhatsApp API，不會聯絡真實收件人。範本尚未提交 Meta 審核；發送、失敗及送達狀態均為模擬。**

## 舊版資料保留

同一瀏覽器、同一網址下的舊版需求、供應商、草稿及操作紀錄會保留，介面及業務文字會遷移為繁體中文；訂單編號、數量及下一個編號不會因遷移而重設。

附件原始檔名、網址、聯絡欄位及資料結構值保持原樣。不同網址（例如另一個部署平台或 GitHub Pages）屬於不同瀏覽器儲存空間，不會自動搬移資料。

## 發佈到 GitHub Pages

本專案使用靜態檔案，無需建置或安裝前端依賴。

1. 將專案檔案提交到 GitHub 儲存庫的 `main` 分支。
2. 打開儲存庫 **Settings → Pages**。
3. 在 **Build and deployment** 中，將 **Source** 設為 **Deploy from a branch**。
4. 將分支設為 **main**，目錄設為 **/docs**，點擊 **Save**。
5. 等待 Pages 部署完成，使用該頁面返回的網站連結存取原型。

`docs/.nojekyll` 用於直接發佈靜態資源。所有頁面資產使用相對路徑，適合儲存庫子路徑部署。

## 驗證

在專案目錄分別運行：

```sh
node model.test.cjs
node locale.test.cjs
node whatsapp.test.cjs
```

三套測試覆蓋業務規則、舊版資料及草稿的繁體遷移、通知範本與收件人驗證、匿名資料、待發送／失敗／重試／送達及持久化。

## 原型範圍

- 需求、報價、通知及操作紀錄只保存在目前瀏覽器的 `localStorage`，不在不同設備、瀏覽器或網址之間共用。
- 三種角色之間的切換為演示導覽，不是真實登入或權限隔離。
- 短訊、WhatsApp、電郵及 AI 尚未連接真實服務。
- 附件只記錄檔名、大小和類型，不上傳或儲存檔案內容。
- 公司、學校、報價和聯絡資料為模擬資料；請使用演示資料體驗。
- 接單確認與實際提交報價分別計數。截止或結案後不能繼續接單或提交報價。
- 補派只增加尚未邀請且符合條件的供應商；自動釋放失約名額和定時補派尚未實現。
