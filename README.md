# InstiQuote AI 官網與校園採購工作台

繁體中文、手機優先的公司官網與可操作 Web 原型：官網介紹 InstiQuote AI 品牌、服務流程與功能，並提供老師、供應商、管理員和總後台四類工作台入口。老師可發佈需求、供應商獨立報價、管理員跟進派單，老師比較方案並選擇供應商；工作台包含 WhatsApp 通知中心與帳號權限管理。

官網內容暫作模擬展示，正式公司名稱、地址、聯絡電郵與電話暫不填寫。頁面提供品牌使命、採購流程、功能介紹、私隱說明與常見問題；目前仍為瀏覽器本地原型。

現有公開網站：<https://tkjewelrytop-lab.github.io/instiquote-ai./>。本次新增功能須隨程式碼更新完成部署後，才會顯示在線上版本。

## 本地運行

安裝 Node.js 後，在專案目錄運行：

```sh
node server.cjs
```

瀏覽器打開 <http://127.0.0.1:4173/>。專案無第三方運行依賴，也可直接打開 `docs/index.html`；本地檔案模式的資料持久化行為依瀏覽器而異。

首頁 `docs/index.html` 為公司官網，角色入口連到 `docs/workspace.html`。更新部署後，可使用以下網址直接進入演示工作台：

- [老師工作台](https://tkjewelrytop-lab.github.io/instiquote-ai./workspace.html?role=teacher)
- [供應商工作台](https://tkjewelrytop-lab.github.io/instiquote-ai./workspace.html?role=supplier)
- [管理員工作台](https://tkjewelrytop-lab.github.io/instiquote-ai./workspace.html?role=admin)
- [總後台](https://tkjewelrytop-lab.github.io/instiquote-ai./workspace.html?role=superadmin)

可加上 `view` 指定初始頁面，例如 `workspace.html?role=admin&view=whatsapp`。網址參數只選擇演示工作台，不代表正式登入或權限驗證。

## 操作體驗

1. 先瀏覽公司官網，了解服務流程，再使用角色入口進入工作台；工作台的品牌連結可返回官網。
2. 選擇「老師」，新建報價需求，完成三步表格。演示驗證碼為 `123456`，不會發送真實短訊。
3. 切換「供應商」，在上方選擇演示帳號，使用該帳號綁定的公司確認接單並填寫報價。
4. 切換「管理員」，查看派單、審核供應商、補派，或結束收集並交付現有報價。
5. 回到「老師」，收到五份報價或管理端結束收集後，可比較匿名方案、確認選擇並查看獲選供應商的模擬聯絡資料。
6. 在管理員側欄打開「WhatsApp 通知」，體驗下述通知流程。
7. 切換「總後台」，管理老師、供應商與管理員帳號，設定角色權限及查看帳號操作紀錄。
8. 總後台側欄「重置演示數據」會清除目前瀏覽器中的修改，並恢復示例需求、通知及帳號。

## 帳號與工作台分工

上方「演示帳號」選單可切換目前類型的帳號。頂部四種角色入口分別為：

- **老師**：發佈及查看自己的需求、比較匿名報價、選擇供應商。需求以固定帳號 ID 歸屬；修改或重用老師電郵不會轉移既有需求。
- **供應商**：查看綁定公司的邀請、接單、提交報價及查看公司資料。同一公司可有多個聯絡人帳號，工作台不會任意切換到其他公司。
- **管理員**：按營運、審核或唯讀角色，查看需求、處理供應商資格、管理 WhatsApp 通知及營運報表。
- **總後台**：管理平台帳號、管理員、角色權限及帳號操作紀錄。

入口 **總後台 → 老師／供應商帳號** 支援新增、搜尋、篩選、編輯、啟用及停用帳號。老師帳號綁定學校；供應商帳號綁定公司，同公司可有多位聯絡人。帳號停用後不能繼續在演示工作台執行操作，既有需求及報價保留。供應商帳號狀態與公司審核／停權狀態分開管理。

## 管理員與角色權限

入口 **總後台 → 管理員控制／角色與權限／帳號操作紀錄**。

- 新增或編輯管理員，分配營運、審核或唯讀角色，管理啟用狀態。
- 營運管理員預設可處理需求、供應商、通知及報表；審核管理員負責供應商資格；唯讀管理員只可查看獲授權資料。
- 權限矩陣涵蓋需求查看與管理、供應商審核、WhatsApp 查看與發送、報表匯出、用戶帳號、管理員、角色設定及審計紀錄。
- 總後台可修改角色權限，變更即時反映在頁面及操作限制；一般管理員不能授予高於自身的權限。一般管理員預設只可查看老師及供應商帳號。
- 保留至少一個已啟用的總後台帳號。最後一名擁有人不能停用或降權，總後台完整權限不能移除。
- 支援登出演示、重新登入演示及「重設登入（演示）」。重設會使既有演示登入失效；不收集密碼，也不會發送邀請或重設電郵。
- 帳號新增、編輯、啟停用、角色修改及登入重設會寫入帳號操作紀錄。

同一網址的其他分頁更新帳號狀態後，畫面會同步載入最新資料；已停用帳號不能用舊分頁狀態覆寫回啟用。演示帳號選擇及登入狀態按分頁儲存。

## WhatsApp 通知中心

入口：具有查看權限的 **管理員／總後台 → WhatsApp 通知**。唯讀角色可查看訊息、範本及詳情；只有具發送權限的帳號可建立、模擬發送、模擬失敗及重試。

- 查看老師及供應商的演示通知、收件人、需求編號、訊息內容、狀態及重試次數。
- 內建七個繁體中文範本：需求提交確認、供應商報價邀請、供應商接單進度、收到新報價、報價已備妥、供應商截止提醒、老師選定供應商。
- 點擊「建立通知」，選擇範本、關聯需求及適用供應商，預覽內容後「加入待發送」。收件人及數字由需求自動帶入。
- 待發送訊息可「模擬發送」或在詳情中「模擬失敗」；失敗後可重試，再模擬送達。系統會保存各次操作紀錄。
- 老師提交需求、派單、供應商接單、提交報價、報價備妥、結案及選定供應商等業務動作，會自動建立對應的待發送通知。截止提醒亦可使用範本手動建立。
- 供應商邀請及提醒不包含學校名稱或老師聯絡資料；老師選定前，供應商身份維持匿名。選定通知只顯示獲選供應商的模擬聯絡資料。

**這些功能沒有連接真實 WhatsApp API，不會聯絡真實收件人。範本尚未提交 Meta 審核；發送、失敗及送達狀態均為模擬。**

## 舊版資料保留

同一瀏覽器、同一網址下的舊版需求、供應商、草稿及操作紀錄會保留，介面及業務文字會遷移為繁體中文；訂單編號、數量及下一個編號不會因遷移而重設。

附件原始檔名、網址、聯絡欄位及資料結構值保持原樣。不同網址（例如另一個部署平台或 GitHub Pages）屬於不同瀏覽器儲存空間，不會自動搬移資料。

## 發佈到 GitHub Pages

本專案使用靜態檔案，無需建置或安裝前端依賴。

1. 將專案檔案提交到 GitHub 儲存庫的 `main` 分支。
2. 打開儲存庫 **Settings → Pages**。
3. 在 **Build and deployment** 中，將 **Source** 設為 **Deploy from a branch**。
4. 將分支設為 **main**，目錄設為 **/docs**，點擊 **Save**。
5. 等待 Pages 部署完成，使用該頁面返回的網站連結存取原型。

`docs/.nojekyll` 用於直接發佈靜態資源。所有頁面資產使用相對路徑，適合儲存庫子路徑部署。

## 驗證

在專案目錄分別運行四套測試：

```sh
node model.test.cjs
node locale.test.cjs
node whatsapp.test.cjs
node access.test.cjs
```

四套測試覆蓋業務規則、舊版資料及草稿的繁體遷移、通知範本與收件人驗證、匿名資料、待發送／失敗／重試／送達、帳號及角色權限控制。

## 原型範圍

- 需求、報價、通知、帳號設定及操作紀錄保存在目前瀏覽器的 `localStorage`；演示登入選擇儲存在分頁的 `sessionStorage`。不同設備、瀏覽器或網址之間不會共用資料。
- **四類帳號、登入及權限功能是瀏覽器端流程原型，不是正式驗證或伺服器端存取控制。** 不儲存密碼、不發送登入電郵，請使用模擬資料體驗。
- 短訊、WhatsApp、電郵及 AI 尚未連接真實服務。
- 附件只記錄檔名、大小和類型，不上傳或儲存檔案內容。
- 公司、學校、報價和聯絡資料為模擬資料；請使用演示資料體驗。
- 接單確認與實際提交報價分別計數。截止或結案後不能繼續接單或提交報價。
- 補派只增加尚未邀請且符合條件的供應商；自動釋放失約名額和定時補派尚未實現。

此匯出不包含原始需求 PDF、Sites 專案設定、憑據、個人檔案、部署壓縮包或設備專用瀏覽器測試腳本。
